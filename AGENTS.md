# Repository Guidelines

## Project Structure & Module Organization
- `src/routes` — SvelteKit pages and API endpoints (e.g., `+page.svelte`, `api/*/+server.js`).
- `src/lib` — shared modules (e.g., `db.js` wraps better-sqlite3 and creates `landscape.db` in repo root).
- `static` — public assets (fonts, images).
- `build` — compiled output (generated by Vite + adapter-node).
- `server.js` — HTTPS wrapper using `build/handler.js` and local `ssl/` certs; logs to `logs/access.log`.

## Build, Test, and Development Commands
- `npm run dev` — start SvelteKit dev server (http://localhost:5173).
- `npm run build` — production build to `build/`.
- `npm run preview` — preview the production build locally.
- `npm start` — run `node build/index.js` (adapter-node output).
- `node server.js` — serve HTTPS via `build/handler.js` (requires `ssl/private.key` and `ssl/certificate.crt`).

## Coding Style & Naming Conventions
- JavaScript ESM + Svelte 5; use 2-space indentation and semicolons.
- Follow SvelteKit file-based routing (`+page.svelte`, `+server.js`), kebab-case for folders.
- Prefer `const`/`let`, named exports; import shared code via `$lib` (e.g., `import { getTiles } from '$lib/db.js'`).
- No linters configured; match existing style and avoid large reformatting in unrelated files.

## Testing Guidelines
- No formal test runner yet. Validate via:
  - Dev flow: `npm run dev` then exercise routes and API endpoints.
  - Build flow: `npm run build && npm run preview`.
  - API example: `curl -X GET http://localhost:5173/api/tiles`.
- Keep changes small and cover new endpoints with manual steps in PR description.

## Commit & Pull Request Guidelines
- Use Conventional Commits: `feat: ...`, `fix(api): ...`, `chore: ...`.
- PRs must include:
  - What/why, affected routes/modules, and any DB impact (`landscape.db`).
  - Screenshots/GIFs for UI changes.
  - Local verification steps (`dev`, `build`, API checks).
- Do not commit generated output (`build/`, `.svelte-kit/`), secrets, or binaries.

## Security & Configuration Tips
- Secrets: do not hardcode API keys; prefer env files (`.env*` are gitignored). Avoid committing credentials (e.g., values used in `test.js`).
- TLS: `ssl/` is gitignored; place `ssl/private.key` and `ssl/certificate.crt` locally for `server.js`.
- Logs: `logs/` is gitignored. Create the folder locally if missing.
- Runtime: Node.js 18+ recommended. Install deps with `npm ci` for reproducible builds.
