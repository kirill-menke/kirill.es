# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal website (kirill.es): SvelteKit 3, Svelte 5, Vite 8, adapter-node. Plain ESM JavaScript, no TypeScript.

## Commands

```bash
npm ci                 # install
npm run dev            # dev server, http://localhost:5173
npm run build          # vite build: adapter-node output + every page prerendered, into build/
npm run preview        # serve the production build
npm run lint           # ESLint with --max-warnings 0: any warning counts as a failure
npm run format         # Prettier --write (format:check only checks)
nix build              # build the Nix package (nix/package.nix); `nix run` serves it on :3000
```

There is no test runner. To verify a change, run `npm run dev` or `npm run build && npm run preview` and open the affected routes.

`jsconfig.json` only helps editors resolve `$app/*` and `#lib` (it extends Kit's generated `node_modules/$app/tsconfig.json`, present after the first dev or build run); it is not a build input. Prettier (`.prettierrc.json`) and ESLint both read `.gitignore`; `.prettierignore` only lists the extra files to skip.

There are no git hooks and no CI. Run `npm run lint && npm run format:check` before pushing, and `nix flake check` to build the Nix package when a change touches dependencies or the build.

## Architecture

- **Fully static at runtime.** `src/routes/+layout.js` sets `prerender = true`, so the Node server only serves prerendered HTML and `static/` (plus the request-time `+error.svelte` page for unknown URLs). There is no API, no database, no env config and no secrets. The production systemd unit (`nix/module.nix`) blocks all network access except loopback. Anything that needs request-time code or outbound calls breaks these assumptions. `services.kirill-es.origin` is ignored (adapter-node 6 dropped `ORIGIN`) and only triggers a warning.
- **SvelteKit 3 specifics.** Kit config lives in the `sveltekit()` plugin in `vite.config.js` (there is no `svelte.config.js`), including `compilerOptions.runes: true` for every file outside `node_modules` and `version.name` from `KIRILL_ES_VERSION`, which `nix/package.nix` sets to the flake revision so builds are reproducible (local builds fall back to `Date.now()`). `$lib` no longer exists: import shared code via `#lib/...`, defined in `package.json` `"imports"`. Read page state from `$app/state`; `$app/stores` is gone.
- **Content is data.** `src/lib/tile-data.js` holds the `projects`, `hobbies` and `books` entries (root-relative image paths, tags, `tileType`, `layout`). `src/lib/components/tiles/TileGrid.svelte` renders any list of them: `tiles/index.js` maps `tileType` to the tile component, `layout: 'wide'` spans two columns. The home page passes an ordered `homeTiles` list; the list pages pass a whole collection. Shared tile CSS (grid, header row, tooltips, arrow anchor, pills, the `tile-dark` modifier) is global in `tiles/tiles.css`; the "Section · Name" header is `tiles/TileHeader.svelte`. The VibeReel entry's `tileType` picks one of three looks built from its one still `screen` and `fact` (`glow`, the default, `stencil` or `scrapbook`), so switching is a one-word change. The project tiles never move on their own: only their entrance and hover animate.
- **Entrances are CSS, so content ships in the prerendered HTML.** Do not gate rendering on a client-side `visible` flag. Give the element the global `.enter` class (`src/app.css`) and tune it with `--enter-duration`, `--enter-delay`, `--enter-y` and `--enter-ease` (custom properties inherit, so setting them on a wrapper works). The animation plays on first paint and on client navigation, never on hydration, and is off under `prefers-reduced-motion`. List pages take their timing from `listEntrance()` in `src/lib/entrance.js` (slow stagger when coming from `/` or on a direct visit, quick otherwise; the root layout calls `trackEntrance()`). For the few Svelte transitions left, import `fly`/`fade` from `#lib/motion.js`, which respects reduced motion. Only the content in the middle of the `/flags` wreath, which depends on a measured size, renders client-side.
- **`/flags` uses generated data.** `src/lib/flags/flags.json` and `static/flag-images/*.svg` come from an external flag-circle pipeline (`export_web.py`, not in this repo). Do not edit them by hand. `flags.json` is excluded from Prettier. The home-page Flags tile has four looks (`badges`, `fan`, `corner`, `chips`: `Flags*Tile.svelte`), switched by its `tileType` in `tile-data.js`. They get the flag count and their few flags from `virtual:flags-tile`, a small plugin in `vite.config.js` that picks them out of `flags.json` at build time, plus the JSON-free helpers `src/lib/flags/ring.js` (`imageUrl`) and `colour.js`. That keeps `flags.json` out of every page but `/flags`; never import `#lib/flags/index.js` from a tile.
- **`/projects/vibe-reel` embeds the real VibeReel phone app.** `static/vibe-reel-demo/` is the output of the vibe-reel repo's `demo/` build (its `demo/README.md`): the unchanged phone app on a snapshot of the Jellyfin library, with the e2e fakes answering its API in the page and a service worker scoped to `/vibe-reel-demo/` mapping artwork and video onto static files (each title plays its trailer from `media/`, ~290 MB of the ~330 MB). Do not edit it by hand; rebuild it there with `DEMO_OUT=…/static/vibe-reel-demo`. It is excluded from Prettier and ESLint. `LivePhone.svelte` shows it (`/vibe-reel-demo/index.html?frame`, scaled from the iPhone's 393 px) as the iPhone of the "One engine" section's Shape-shifter (`engine/Morph.svelte`, tabs iPhone, TV, Browser), loaded after the page; the prerendered page shows the poster `iphone-demo.webp` until the demo reports `ready` by `postMessage`. Morph shrinks its frame onto the phone's measured screen; for TV and Browser it fades the phone out, `inert` with its media paused, never unmounted, and once the app is up it stops moving on by itself. Hovering, focusing or clicking a tab picks it for good and ends that cycling (a picked morph runs 1.5× as fast), and only the picked device's paragraph shows. The "try it out" note (`phone-note/Note.svelte`) stands beside the phone, sized from its width, and draws itself the first time the phone is on screen with the app up. The app takes the mouse as soon as it is over the phone: `PhoneCursor.svelte` hides the demo's own cursor and draws a grease pencil (`cursor/pencil.js`) on a canvas it puts inside the same-origin iframe (`cursor/layer.js`). A frame narrower than 150 px links to the demo instead. The hero has no phone: the TV with the soundbar under it on the left (`Soundbar.svelte` keeps its drawn outline as far in as `TvSketch`'s `SIDES`, so it runs under the TV's), the source link at the top of the stage, left-aligned with the features, three numbered features on the right (`hero/Features.svelte`), and the bias light (`hero/BiasLight.svelte`) samples each shot in a canvas so the glow follows the picture. The TV powers on, on its screen only, once its frame is drawn (`TvSketchPen`'s `DRAWN`), and its shots, 8 s each, change through static (`devices/TvPicture.svelte`). The TV screenshots `tv-home`, `tv-detail` and `tv-player.webp` come from that repo's `demo/tv-shots.mjs`. The film strip's frames (`TvScreens.svelte`, its parts in `tv-screens/`) show `<name>-bleed.webp`, the shots carried on past their edges by `node scripts/bleed-shots.mjs` (needs ImageMagick); run it again whenever a shot changes. Further down, `ArchDiagram.svelte` draws the architecture as a still pencil sketch, its edges from `arch/data.js`, `DownloadBar.svelte` the torrent from `downloads/`, and `Pipeline.svelte` the trailer timeline. The page's last line lies halfway between the last ticket and Rosie in the footer, placed from the article's foot (`+page.svelte`'s `.vr-end`, which counts on the footer's padding).
- **VibeReel's sections pull focus as they scroll in, and that is what Firefox paints slowest.** `Section.svelte` runs it scroll-driven (`animation-timeline: view()`, no script): the heading, the lede and each block of the body start faint and blurred and are sharp 14 rem into the window. Nothing leaves the DOM. Firefox scrolls ahead of its painting, and blurring and fading the large drawings and tickets on every scrolled frame about doubles its time for a frame (measured 2026-11-11 with software rendering: ~75 ms against ~40 ms, Chrome ~20 ms either way), so on a fast scroll parts show late, blank or still soft. Taking the pull off the body's blocks (`animation: none` on `.body > *`, leaving the heading and the lede) gave that half back when it was tried; the page ships with it on every block.
- **Global styles.** Tokens are in `src/app.css`: colours (`--color-*`, including `--color-border` and the `--color-device-*` mock-up colours), fonts (`--font-primary`, `--font-secondary`, `--font-mono`), `--shadow-float`, `--flag-outline`, easings, plus `.enter` and `.visually-hidden`. Use a token when the value matches. Components use scoped `<style>` blocks. Fonts are WOFF2 in `static/fonts`, preloaded in `src/app.html`; NanumMyeongjo is subset to U+0000-2FFF (no Hangul).
- **Page-only components live next to their route.** `src/routes/flags/` and `src/routes/projects/vibe-reel/` hold their own components (Kit ignores files without a `+` prefix); `src/lib/components` keeps only shared pieces (`NavBar`, `Footer`, `tiles/`, `sketch/` and `TweakPanel`). `sketch/` holds the hand-drawn line helpers (`sketch.js`), the pen of the sketched sets (`TvSketchPen`, whose `DRAWN` says when a set's own lines are down) and the sketched TV with its LG nameplate and top-rail grooves (`TvSketch`): the VibeReel hero (`TvFrame`), its Shape-shifter and its home tile all draw that one set. They paint with `--vr-ink`, `--vr-cream` and, on the nameplate, `--vr-wash`, so a user outside the page sets those; a user that gives `--vr-light` has the set's power light lit (the VibeReel page does). VibeReel's shared panel class, `vr-panel`, is defined once in its `+page.svelte`: a sepia ticket that its `::before` (the shadow) and `::after` (the sheet and its perforation) draw with border images, so that it looks the same in every browser; a widget lays its own sheet in it through `--panel-color` and `--panel-image`, never a background. Beside it stand the page's colours (the page in greys, every `.vr-panel` in sepia) and its sketchbook tokens: `--vr-paper` and `--vr-paper-grain` (the architecture diagram's sheet, which the download bar and the trailer timeline share), `--vr-wash` (its gold wash, for a few highlights only) and the diagram's pencil (`--vr-pencil`, `--vr-pencil-frame`, `--vr-pencil-faint`), which the drawings under it take up.
- **`TweakPanel` is for trying out variations while developing.** A dev-only floating "Tweaks" window of options, sliders and switches with foldable sections, each heading saying how many of its items are off their defaults; drag its header to move it anywhere (kept on screen and remembered under `<storage>:position`, double-click returns it to the bottom-right corner). No page uses it at the moment. Its header comment documents the items and how to wire it: each item's default is the page as it ships (the built site has no panel), components read the values through context, and once the variations are settled the picked values are baked into the code and the panel goes, as on the VibeReel page (twice; the branch `vibe-reel-refine` keeps its last panel, a `tweaks.js` beside the page with `useTweaks()` for its components). A choice's options form a grid, three columns when every label fits and otherwise two, with a dot on the default. So name each option in a word or two (≤ ~13 characters for three columns), not "Current", and put the detail in `about`. An item's `where` (a selector) names the part of the page it changes: a change in the panel brings it into view, clear of the panel, and "show" beside the item's heading goes there.

## Conventions

- **Runes only.** The compiler runs every component in runes mode (`$props`, `$state`, `$derived`, snippets and `{@render}`), so legacy `export let`, `<slot>` or `$:` fail to compile. A plain `let` that markup reads after it changes must be `$state`. Key every `{#each}` block (`svelte/require-each-key`). ESLint also enforces `svelte/no-top-level-browser-globals`, because prerendering runs components in Node.
- **New build inputs need adding to the Nix allowlist.** `nix/package.nix` builds from an explicit fileset (`package.json`, `package-lock.json`, `vite.config.js`, `src`, `static`). Add any new top-level file the build needs there, or the Nix build fails. Keep every npm package in `devDependencies` and leave `dependencies` absent: the adapter-node bundle inlines all imports and the Nix package ships no `node_modules` (anything in `dependencies` would stay external). The Nix install check imports the server bundle, so a missing module fails the build, not the deploy.
- **Branches and releases.** Work directly on `main`; there is no `dev` branch. Pushing deploys nothing: production is deployed by hand from a separate config repo that pins a commit of `main`, so only commit finished work there. There is no staging.
- **Commits.** Use Conventional Commits, with `!` for breaking changes (`feat!:`, `build!:`).
